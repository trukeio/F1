# ADR-0007: S3 API semantics

- Status: accepted
- Date: 2026-10-13
- Deciders: Rolf Veen

## Context

Phase 4 implements the S3 compatibility API (doc/plan.md, "S3 compatibility API"). The plan fixes the mapping (bucket = namespace, key = path, writes = commits), the operation list, SigV4 with every payload mode, ETags and the multipart internals. This ADR records the rules the plan leaves open.

## Decision

### Requests and authentication

1. **Listener and addressing.** S3 has its own listener (`[server.s3] listen`, default `127.0.0.1:9000`; empty disables it). Path-style addressing always works; with `domain` set, `<bucket>.<domain>` works too. One region (`region`, default `us-east-1`) is accepted in credential scopes and reported by GetBucketLocation.
2. **SigV4 only.** Header and presigned-query authentication; anonymous requests and SigV2 are refused. Presigned URLs last at most 7 days. The clock skew allowed is 15 minutes.
3. **Canonical URI.** The verifier tries two canonical URIs: the path re-encoded segment by segment with the AWS URI encoding (what the SDKs sign, whatever the client escaped), and the path exactly as received (clients that sign what they send, such as a literal `+`). Both describe the same request path, so accepting either does not widen what a signature authorizes.
4. **Payload verification.** Signed payload hashes, Content-MD5 and `x-amz-checksum-*` values (headers or trailers) are checked after the body has been ingested and before the commit. aws-chunked chunk and trailer signatures are checked at the end of each chunk, so a forged chunk fails the read. A body that fails a check is stored but never referenced; GC removes it.

### Buckets

5. **Unknown and inaccessible buckets look the same** (NoSuchBucket), as for namespaces in the native API (ADR-0006).
6. **CreateBucket** creates a namespace with the S3 preset and needs a server administrator, like namespace creation in the native API. `create_bucket = false` disables it and DeleteBucket.
7. **DeleteBucket** needs a server administrator and an empty bucket: every ref points to an empty tree, or there are none. Open multipart uploads are discarded with the bucket, as in S3. The repository is detached and its directory moved to `repos/.deleted-<ns>-<suffix>`; nothing is erased. The operator removes it, or restores it with a rename and `f1d repo attach`.
8. **Bucket aliases** (`[[server.s3.alias]]`) expose a namespace and ref under another name, for example a branch. They cannot be created or deleted through S3.

### Writes

9. **Commits.** In autocommit namespaces, writes go through the group committer, which evaluates conditional writes (`If-Match`, `If-None-Match: *`) in order inside the batch. Otherwise each request is one commit, made with compare-and-swap on the current head and retried on conflict. DeleteObjects is one commit; a key refused by a lock is reported in the response and left out.
10. **Errors from the core.**
    - A lock conflict is `403 AccessDenied` with `path is locked by <owner>`.
    - A frozen repository answers `503 SlowDown`.
    - A key the tree layout cannot hold is `400 InvalidArgument`, with a message that points to `layout = flat`.
    - A hierarchy conflict (`a` is a file and `a/b` is written) is `409 InvalidRequest`.
    - Deleting a missing key succeeds without a commit.
11. **Metadata.**
    - `Content-Type`, `x-amz-meta-*` and the standard headers Cache-Control, Content-Disposition, Content-Encoding, Content-Language and Expires are kept. The standard headers are stored in `attrs.meta` under `:<name>` (doc/format.md).
    - The `aws-chunked` coding is removed from Content-Encoding.
    - User metadata is limited to 2 KB.
    - Metadata headers are returned in lower case, as S3 does: botocore takes metadata names from the header names as received.
    - Objects stored without a content type are served as `binary/octet-stream`.

### Reads

12. **ETag and LastModified of entries written by other protocols.**
    - The ETag is the hex MD5 from the File's DigestRecord, computed on demand if the record is still missing.
    - LastModified is the committer time of the newest first-parent commit that changed the path (`repo.LastModified`). It is computed with one history walk per listing page and cached.
13. **Conditional requests** follow RFC 7232 in the order S3 documents: `If-Match` wins over a false `If-Unmodified-Since`, and `If-None-Match` over `If-Modified-Since`. CopyObject source conditions fail with 412 only.
14. **Ranges.** A single byte range is served. Several ranges are ignored and the whole object is returned, as S3 does.
15. **GetObject with `partNumber`** is supported only for part 1 of a single-part object; part boundaries of multipart objects are not kept.

### Checksums

16. **Stored when sent.** F1 stores and returns the checksums a client sends; it does not compute a default CRC64NVME for objects without one, as AWS has done since 2025. With the SDK defaults, clients send a CRC32.
17. **Multipart checksums.**
    - COMPOSITE checksums are the algorithm over the part checksums, followed by `-<parts>`.
    - FULL_OBJECT checksums (CRC32, CRC32C, CRC64NVME) are combined from the part CRCs and sizes over GF(2), without reading the content.
    - CRC64NVME is full-object only; SHA-1 and SHA-256 are composite only.

### Multipart uploads

18. **State.**
    - Uploads are in `cache.db` (schema version 2; version 1 caches are upgraded in place).
    - A part is acknowledged after its pack is durable.
    - Completion checks the order and existence of every part before part sizes. The minimum part size is 5 MiB (except the last).
    - The upload is removed after the object is committed.
    - Uploads older than `upload_expiry` (7 days) are removed by an hourly sweep.
19. **Digests.** The completed File's DigestRecord is computed in the background, one job at a time per repository. A request that needs it earlier computes it.

### Copies

20. **CopyObject** within a repository reuses the source File, so nothing is copied and the ETag is kept. Across repositories, the content is streamed into the destination (objects are per repository, D6). UploadPartCopy always ingests the requested range, because a part needs its own MD5 and checksum.

### Versioning

21. **Versioned buckets.** A bucket is versioned exactly when its namespace keeps history (retention other than `none`). PutBucketVersioning is NotImplemented, since the retention policy decides. Unversioned buckets use version id `null`.
22. **Version ids** are the base32 of the commit that wrote the version. GetObject and HeadObject accept any commit id of the bucket. A commit that deleted the key answers as a delete marker would: 405 with `x-amz-delete-marker: true`.
23. **Version ids in responses.** Writes, copies, completions and deletions return `x-amz-version-id`, because the commit is known. GET and HEAD without `versionId` do not return it: finding the version would need a history walk.
24. **ListObjectVersions** walks the first-parent history of the bucket's ref. Every change of a key is a version, and every deletion is a delete marker. Its cost grows with the length of the history; the native log API is the tool for long histories.
25. **Deleting a version.**
    - History is immutable, so only the newest version of a key can be deleted, which makes the version before it current, as in S3.
    - Deleting a delete marker restores the object.
    - Deleting the current version restores the previous one, or removes the key.
    - Deleting an older version is NotImplemented; old versions expire with the retention policy.
26. **Autocommit and versioning.** Writes batched into one group commit share a version id, so of two writes to one key in the same batch only the last is a version. Versioned namespaces normally do not use autocommit.

### Not implemented

27. ACLs, policies, tagging, lifecycle, CORS, website, logging, notifications, replication, encryption settings, object lock, SelectObjectContent and the other subresources answer `501 NotImplemented`. Access is governed by F1's ACLs (ADR-0006).

## Consequences

- The AWS SDK for Go v2, the AWS CLI, rclone and the MinIO client work for the operations above: cp, sync, mirror and check all succeed, and a second sync transfers nothing.
- A selected subset of the Ceph s3-tests passes (`test/s3tests.txt`).
- Versioning costs grow with history length, which suits the SVN-style use with moderate histories and not buckets with millions of versions per key.

## Alternatives considered

- **Computing a default CRC64NVME for every object.** This matches AWS since 2025, but costs CPU on every write, and no tested client needs it.
- **Deleting old versions by rewriting history.** This contradicts immutable history and would change commit hashes that Git clients may hold.
- **Storing part boundaries for `partNumber` reads.** This would need a format addition; no tested client uses it.
- **Letting namespace administrators delete buckets.** Deleting a namespace removes its history from the server, so it stays with server administrators, like creation.
